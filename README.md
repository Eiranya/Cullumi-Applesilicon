# Cullumi for macOS

Cullumi 是一款**仅在本机运行**的照片筛选应用。它递归扫描照片目录，生成不裁切的缩略图，检查画质，找出完全重复照片和相似连拍，最后由你决定保留或隔离哪些照片。自动分析只评估技术指标，所有决定仍由你确认。

当前版本：**v1.1.7**（arm64 / macOS 14+）· [下载最新版](https://github.com/Eiranya/Cullumi-Applesilicon/releases/latest)

> 本仓库是 [Yuumi0221/Cullumi](https://github.com/Yuumi0221/Cullumi) 的 macOS 移植版，功能与界面与上游保持一致，并加入 Apple Silicon 硬件加速与若干 macOS 适配。移植范围与差异见 [`MACOS-使用说明.md`](MACOS-使用说明.md)。

---

## 功能

- **画质分析** —— 清晰度、曝光、对比度、暗/亮部剪切、亮度分布与感知哈希
- **完全重复检测** —— 按内容哈希跨目录识别字节级重复
- **相似连拍分组** —— 感知哈希 + 结构相似度，含时间邻近与文件序号邻近判定
- **RAW/JPEG 拍摄变体** —— 同一曝光的多种格式只显示一张卡片，相似组与侧栏封面同一口径
- **大图查看** —— 预览秒开，放大按显示尺寸自动换源（2048 / 4096 / 原图），支持真实 1:1 并如实提示当前画质；预览打开即铺满窗口，底部状态行可在设置中隐藏
- **眨眼检测** —— 人脸定位 + 眼部分类（CoreML 硬件加速）
- **动态照片** —— iPhone Live Photo 与 Android Motion Photo，支持改封面与保留声音缓存
- **决策与隔离** —— 单张/批量决定、CSV 导入导出；隔离后台进行、浮条显示进度、可撤销；隔离历史恢复同样后台进行
- **分批浏览** —— 照片库每批 120 张，浏览到已加载末尾自动续页、不回卷

## 安装与首次打开

下载并解压 `.app` 后双击 `Cullumi.app`。应用使用 **ad-hoc 签名**（未经 Apple 公证），首次打开会被 Gatekeeper 拦截——**这是预期行为，不代表文件损坏**：

```bash
# 方式一（最简单）：Finder 中右键 Cullumi.app →「打开」→「打开」，此后不再询问

# 方式二：移除隔离属性
xattr -r -d com.apple.quarantine /Applications/Cullumi.app
```

## 使用

1. **导入** —— 「从文件夹导入」选择照片目录，整个目录树递归扫描；扫描可随时取消，再次扫描复用未变化照片的结果
2. **筛选** —— 照片库组合决定状态、分析结果与格式筛选；除「智能建议」外，各组别默认按文件名排序，可按建议 / 名称 / 大小 / 拍摄日期切换
3. **查看** —— 快捷键：`W/↑` 保留、`S/↓` 移除、`A/←` 上一张、`D/→` 下一张、`F` 查看原图（载入后自动落到 1:1）、`0` 适应窗口。放大自动换源，底部状态行如实提示当前画质（可在设置中关闭）
4. **隔离** —— 「隔离已标记移除」并检查清单；确认后文件在后台移入原目录下的 `_照片筛选隔离/`，浮条显示进度，完成后可撤销；隔离历史中可恢复任意批次

### 数据存放位置

| 内容 | 路径 |
|---|---|
| 配置、项目数据库、缩略图、预览缓存、日志 | `~/Library/Application Support/Cullumi/` |
| 隔离文件 | 原照片目录下的 `_照片筛选隔离/` |

**项目数据库与缓存删除后，决定与隔离历史会一并丢失。**

## 网络与隐私

- 只监听 `127.0.0.1`，接口使用每次启动随机生成的会话令牌
- **不收集、不上传任何数据**，照片处理全部在本机完成
- 仅「检查更新」访问 GitHub API，其余功能不联网

## 支持格式与限制

| 类型 | 扩展名 | 解码器 |
|---|---|---|
| 常见图片 | JPG、JPEG、PNG、WebP、TIFF、BMP | Pillow |
| HEIF 系 | HEIC、HEIF、HIF 等 | pillow-heif |
| RAW | DNG、CR2、CR3、NEF、ARW、RAF、ORF、RW2、PEF | rawpy / LibRaw |

**RAW/JPEG 拍摄变体**

- 同名且拍摄时间一致（5 秒内）的 RAW 与非 RAW 关联为一个变体组，**两者可位于不同目录**；判定依次回退 EXIF 拍摄时间 → 文件修改时间 → 文件名主干，**时间冲突即拒绝配对**
- 照片库、相似组、侧栏封面均按曝光只出一张卡片，代表文件取「可解码、非 RAW、分辨率最高」的那份；决定默认同步整组，组内其余格式以卡片徽标列出
- **RAW 不提供预览**：浏览器无法解码，关联格式徽标是纯文字提示；某曝光没有可读取的非 RAW 文件时，代表文件本身就是 RAW，仍会显示

**计数口径**：侧栏与照片库按**变体组**计（与屏幕上的卡片一一对应）；格式分类计数按**真实文件数**（「我有多少 RAW」是关于磁盘的问题）。侧栏恒等式：`保留 + 移除 + 未决定 = 可读`。

**浏览边界**：「下一张」走到已加载末尾自动续页（连按只发一个请求、按压步数照补），全部加载完则停住提示「已经到底了」、**不回卷**；「上一张」在第 1 张时循环到最后一张；关闭预览或换筛选会作废在途续页，但批次仍并入列表供滚动浏览。

### 已知限制

| 限制 | 说明 |
|---|---|
| RAW 配对需重扫一次 | 缓存版本升级后首次扫描提示「需要重新扫描」，执行一次以补齐 RAW 拍摄时间（只读文件头，不解码整图） |
| 非整数 DPR 无法像素级 1:1 | DPR 1.5 这类小数下图片框为小数尺寸，浏览器仍会做极轻微缩放 |
| RAW 无原始像素预览 | RAW 无法解码，预览最高清到代表文件（通常是 JPEG）的清晰度 |
| 超过原图分辨率无法更清晰 | 放大到照片自身像素以上即物理上限（状态提示「已到原始像素上限」） |
| 输入设备自动识别可能判错 | 浏览器不暴露滚轮事件来源；判错时请在 设置 →「图片查看」手动指定触控板 / 鼠标 |
| macOS 14 未实测 | 最低版本来自 onnxruntime 轮子可用性，未在真实旧系统上验证 |
| 模型不支持替换 | `models/` 下眨眼检测与 NIQE 模型已随包分发 |

**动态照片**：支持 iPhone Live Photo（同目录同名 HEIC/HEIF/JPEG + MOV）与 Android Motion Photo（带标准 XMP 的 JPEG 内嵌视频）；首次播放生成保留声音的 WebM 缓存；将视频帧写入原图后，静态图会采用该帧的分辨率，可能低于原始照片。

**分析范围**：自动分析只检查技术指标，**不判断构图、表情偏好或纪念价值**；小脸、侧脸、遮挡与低光照片可能无法可靠判断。

## 目录结构

```
Cullumi-Applesilicon/
├── app.py                    # 入口：配置日志、启动本地服务、创建 pywebview 窗口
├── cullumi/                  # Python 后端（解码分析 / 变体分组 / 相似分组 /
│                             #   人脸眨眼 / 扫描调度 / SQLite / 卡片预览派生）
├── web/                      # 前端（原生 JS/CSS，无构建工具）
├── models/                   # 眨眼检测 + NIQE 模型（随包分发）
├── tests/                    # 单元测试
├── docs/arch/                # 历史归档（移植计划、QA 报告、性能剖析）
├── build-macos.sh            # 一键构建：依赖 → 检查 → 打包
├── setup-macos.sh            # 依赖安装
├── verify-macos.sh           # ruff + 全量单元测试
├── verify-change-set.sh      # 与上游差异门禁
└── smoke-test-macos.sh       # 冒烟测试
```

## 从源码运行

```bash
# 1. 安装依赖（首次必做）
./setup-macos.sh

# 2. 启动
CULLUMI_PYTHON=/path/to/python3 ./build-macos.sh   # 或直接 python app.py

# 检查 / 门禁
./verify-macos.sh          # ruff + 全量单元测试
./verify-change-set.sh     # 与上游差异门禁（冻结目录、差异与新增白名单、README 一致性）
```

**Python 环境**：`numpy`、`Pillow`、`pillow-heif`、`rawpy`、`pywebview==6.1`、`onnxruntime`、`imageio-ffmpeg` 及 PyObjC 系列，完整列表见 `requirements-macos.txt`。

> `pywebview` 依赖的 `proxy_tools` 与 `bottle` 需 `--no-deps` 分步安装，**请勿手工 `pip install -r requirements-macos.txt`**，直接跑 `setup-macos.sh` 即可。
